# 03｜生命层：身份、需求、目标与记忆

> "生命感知"在本项目里是一个**工程概念**：角色持续感知自己的身体、环境、需求、目标、时间与经历，并让这些状态影响下一步行为。

---

## 1. Identity / Character Profile

人物设定是稳定配置，**不要每次调用 LLM 重新生成**。

```json
{
  "name": "UnityChan",
  "background": "生活在实验世界中的虚拟角色",
  "traits": ["好奇", "友好", "谨慎"],
  "preferences": {
    "likes": ["探索新区域", "整洁"],
    "dislikes": ["高风险行为"]
  },
  "long_term_goals": ["了解世界", "保持自身安全", "完成用户交付的任务"]
}
```

分三层存放，不要混：

```text
immutable identity      稳定人设（不随经历改变）
slow-changing prefs     偏好（可缓慢漂移）
runtime state           当前需求 / 目标 / 情绪（高频变化）
```

**反例：** 把"今天看到一个红杯子"写回 Personality。

---

## 2. Needs System

没有 Needs 时，自主 Agent 在没有命令时通常只能停着。

第一版只做与世界机制真正相关的需求：

```text
Curiosity       好奇：未探索区域 / 未知物体
Safety          安全：危险接近 / 平衡失稳 / 人类喊停
TaskPressure    任务压力：用户交付的任务未完成
Energy          仅当世界存在休息/能耗机制时才做
Social          仅当世界存在交互对象时才做
```

```json
{
  "name": "curiosity",
  "value": 0.72,
  "decay_per_min": -0.01,
  "triggers": ["unknown_object", "unexplored_area"]
}
```

### 2.1 数值不要交给 LLM 算

```python
def update_curiosity(value: float, novelty: float, dt: float) -> float:
    value += novelty * 0.15
    value -= dt * 0.002
    return max(0.0, min(1.0, value))
```

LLM 可以解释复杂情境，但 Needs 数值必须由确定性逻辑维护，才能被复现、被调参、被单测。

## 3. Goal Manager

接收：

```text
Needs / Identity / Belief / Memory / Human Commands / Current Goal / Safety Constraints
```

产生候选目标：

```text
InspectObject  ExploreArea  SearchObject  FinishTask  ReturnHome  AskHuman  Wait
```

第一版可以不用 LLM 选目标，用可解释的加权：

```text
GoalScore = NeedUrgency + UserPriority + Importance + Novelty - Risk - EstimatedCost
```

```python
def score_goal(goal):
    return (
        goal["need_urgency"]
        + goal["user_priority"]
        + goal["importance"]
        + goal["novelty"]
        - goal["risk"]
        - goal["cost"]
    )
```

这样"为什么选这个目标"是可调试、可复现的。

## 4. Human Command Arbiter

用户命令**不要直接驱动骨骼**，统一转成命令事件：

```json
{
  "command_id": "cmd_301",
  "source": "human",
  "type": "GOAL_OVERRIDE",
  "priority": 100,
  "text": "先别探索了，去看看厨房",
  "created_at_ms": 1789891200123
}
```

三种基本类型：

```text
STOP     立即取消当前 Skill / Goal（本地也必须能执行）
COMMAND  高优先级 Goal
SUGGEST  写入工作记忆 / 候选信息，由 Agent 自己决定是否采纳
```

优先级建议：

```text
Emergency STOP > Safety > Human COMMAND > Existing high-priority task > Autonomous needs
```

## 5. Working Memory

只保存当前任务相关内容：

```text
当前 Goal
最近看到的重要对象
最近 5~20 个 Skill 结果
当前失败原因
用户最近指令
```

不要把整个历史聊天无限塞进 prompt。

```json
{
  "goal": "拿到红杯子",
  "recent_events": [
    "WalkTo cup_12 succeeded",
    "Reach cup_12 failed: OUT_OF_REACH"
  ],
  "focus_objects": ["cup_12", "table_3"]
}
```

## 6. 长期记忆：四层

| 层 | 回答的问题 | 例子 |
| --- | --- | --- |
| Episodic 经历 | 我经历过什么 | "在厨房发现红杯子。尝试打开 Door_03，但门锁住。" |
| Semantic 知识 | 我知道什么 | "厨房在走廊北侧。Door_03 需要钥匙。" |
| Procedural 技能经验 | 怎样做更容易成功 | "Reach 前距离 < 0.8 m 成功率更高。" |
| Working 短期 | 当前任务上下文 | 见上一节 |

### 6.1 SQLite 第一版

第一版**不需要**向量数据库。

```sql
CREATE TABLE episodes (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp_ms  INTEGER NOT NULL,
    location      TEXT,
    goal          TEXT,
    summary       TEXT NOT NULL,
    importance    REAL DEFAULT 0.5,
    success       INTEGER,
    objects_json  TEXT
);
```

```python
import sqlite3

conn = sqlite3.connect("memory.db")

def write_episode(ts, location, goal, summary, success):
    sql = ("INSERT INTO episodes "
           "(timestamp_ms, location, goal, summary, success) "
           "VALUES (?, ?, ?, ?, ?)")
    conn.execute(sql, (ts, location, goal, summary, int(success)))
    conn.commit()
```

等数据量与检索问题真实出现后，再加 embedding / 向量检索 / reranking。

### 6.2 什么时候写记忆

**不要每帧写。** 事件触发：

```text
Goal Completed / Goal Failed
新地点 / 新对象
重要环境变化
用户提供重要事实
重复失败
异常事件
一次探索结束
```

例如连续 300 帧看到红杯子，最终只写一条：

```text
"厨房桌面上有一个红色杯子。"
```

### 6.3 检索

输入：

```text
current goal / location / visible objects / recent failure
```

第一版可用时间、关键词、location、object tags、success/failure、importance：

```sql
SELECT * FROM episodes
WHERE location = ?
ORDER BY importance DESC, timestamp_ms DESC
LIMIT 8;
```

后续升级为语义检索时，接口不变（`Memory.Recall(context) -> list[MemoryItem]`）。

## 7. 记忆与遥测的关系

Skill 遥测（见 `04`）是 Procedural Memory 的原料：

```json
{
  "skill": "Reach",
  "target_type": "cup",
  "duration_s": 1.82,
  "success": true,
  "retry_count": 1,
  "start_distance_m": 0.71,
  "final_error_m": 0.031
}
```

聚合后可得到"距离—成功率"曲线，用于：

- 调参（StopDistance、Reach 容差）；
- 找失败模式；
- 形成 Procedural Memory；
- 为 ML-Agents 2 的训练提供 reward shaping 与课程设计依据（见 `06`）。

## 9. 验收标准

### 9.1 Brain 不接 LLM 也能运行

```text
发现未知物体 → Curiosity 增加 → 生成 Inspect Goal → LookAt → WalkNear → 收到 Skill 反馈
```

### 9.2 Human Command

```text
自主 Explore → 用户 COMMAND: 去厨房 → Cancel/暂停 Explore → 执行 Inspect Kitchen
```

### 9.3 Memory

```text
第一次发现杯子 → 写 episode
下次进入厨房 → 能检索到相关经历
```

### 9.4 WorldTruth / Belief 分离

```text
测试：把物体偷偷移走，但角色没有看到移动过程
预期：WorldTruth 已变化
     Belief 保留旧位置且置信度下降
     直到重新观察才更新
```
