# 07｜路线图：阶段划分与验收

> 每个阶段都必须**可独立演示**，不允许"全都做完才能看到东西"。
> 阶段号在本项目内是稳定约定：`落地方案` 目录的文件名与之一一对应。

---

## 1. 五阶段全景

| 阶段 | 主题 | 核心交付 | 对应文档 |
| --- | --- | --- | --- |
| Phase 1 | Vision → Belief | 相机取帧、快/仔细两级理解、主观信念 | `落地方案/01` |
| Phase 2 | Body：注视与操作 | `LookAt` / `Reach` / `Grasp` 闭环（RigGraph） | `落地方案/02`（待写） |
| Phase 3 | Locomotion | `WalkTo` + 导航 + 平衡 + `BodyState` | `落地方案/03`（待写） |

阶段之间**只通过文档化的契约耦合**：

```text
Phase1 → Phase2 ：world_position + position_confidence + center_uv + IsWorldPointCentered()

Phase3 → Phase4 ：BodyState + 事件流（Skill 结果、感知事件）
Phase4 → Phase5 ：BodyState 观测面 + 遥测数据集
```

## 2. Phase 1：相机 → 视觉 → 理解闭环

**目标**：让角色拥有可用的第一人称视觉理解，并把"看见的东西"变成可以错、可以不确定、会衰减的主观信念。

**验收（摘要）**：

```text
A 图像链：连续运行 10 分钟不卡主线程、Python 掉线不影响 Unity、丢帧率 < 5%
B 感知链：目标进入视野 1 s 内被检出、静止 60 s 内 track_id 变化 = 0、
         未知物只触发一次仔细理解、快照中不含 Unity 实例 ID
C 空间链：重投影误差 p95 ≤ 3%、深度误差有实测基线、小目标 position_confidence < 0.4
D 理解闭环：触发正确、输出含 uncertainties、几何字段不被语义覆盖、无 VLM 后端也能跑
E 时序：rtt p95 ≤ 150 ms、陈旧结果全部被丢弃、旧结果不误报 TARGET_LOST
F Belief：0.5 s 转 uncertain、约 8 s 转 unknown、真值移走时 Belief 保留旧位置
```

完整量化标准见 `落地方案/01_第一阶段_相机-视觉-理解闭环.md` §10。

## 3. Phase 2：注视与操作

**目标**：让角色能"看向"和"够到"，并把这两个行为做成可验证 Skill。

**交付**：

```text
RigGraph 骨架接入（RigGraphManager + Control Rig + Effector / 变量）
HeadEffector + Aim Math  → LookAt（视觉闭环验收）
RightHandEffector + Two Bone IK → Reach（含 Reachability 粗判与恢复）
GraspPoint + FixedJoint → Grasp（含 follow test）
Skill Scheduler + 资源锁 + Verifier + 失败码
```

**验收**：

```text
LookAt ：目标回到画面中央并持续 N 帧才算成功（不是"发了命令"）
Reach  ：手到目标 5～8 cm、肘方向稳定；不可达时返回 OUT_OF_REACH 而不是硬拉
Grasp  ：物体跟随手持续 T 秒；掉落记 OBJECT_SLIPPED，不算成功
资源锁 ：LookAt 与 WalkTo 可并行；两个右手 Skill 不能同时运行
```

---

## 4. Phase 3：移动与平衡

**目标**：角色能走到指定位置，并在移动中保持可用的身体状态。

**交付**：

```text
NavMesh 路径（只取路径，不用 NavMeshAgent 驱动最终表现）
FootstepPlanner + 腿 IK
BalanceController（support polygon / COM 投影）
BodyState 汇总与上报（10～20 Hz）
WalkTo Skill（含 NO_PATH / PATH_BLOCKED / TARGET_MOVED 失败码）
```

**验收**：

```text
WalkTo：到达 stop_distance 内并停稳；被阻挡时能 repath 或返回结构化失败码
平衡  ：平地慢走 10 局无摔倒；轻推后能恢复
BodyState：Brain 只读 BodyState 就能理解身体处于什么状态
```

---

## 5. Phase 4：Brain

**目标**：让角色"有生命感"：有需求、有目标、有记忆，并且**不接 LLM 也能运行**。

**交付**：

```text
AgentState + 事件驱动 Runtime + 检查点
Needs（Curiosity / Safety / TaskPressure）
Goal Manager（可解释评分）
Human Command Arbiter（STOP / COMMAND / SUGGEST）
Fast Policy（类型化决策）+ LLM Planner（结构化输出、可降级）
Memory（Working / Episodic / Semantic / Procedural）+ SQLite
Debug 面板（Decision Source、Plan、Belief、Memory 检索结果）
```

**验收**：

```text
不接 LLM：发现未知物体 → 好奇上升 → 生成 Inspect 目标 → 执行 → 收到 Skill 反馈
接 LLM  ：自然语言命令被解析成结构化 Plan，且失败可回落到 Fast Policy
人机命令：STOP 能立即取消当前 Skill；COMMAND 能覆盖自主探索
记忆    ：第一次发现杯子写 episode；再次进入厨房能检索到
真值分离：偷偷移走物体，Belief 保持旧位置并衰减，直到重新观察
```

## 6. Phase 5：学习

**目标**：把难手工调参的运动（步态、平衡）交给 ML-Agents 2 训练的策略，同时保持 Skill / Verifier 接口不变。

**交付**：

```text
LocomotionAgent（观测 = BodyState，动作 = 意图参数）
训练配置与课程（YAML + Environment Parameters）
.onnx 模型落地 + BehaviorType 切换（训练 / 推理 / 人工）
混合控制（步态策略 + 程序化手部 IK）
回归评测脚本（mlagents_envs，固定种子，N 局统计）
```

**验收**：见 `06_学习与训练_MLAgents2.md` §9（L1～L5）。

---

## 7. 贯穿所有阶段的铁律

```text
1. Brain 不读 WorldTruth（只有 Verifier 与 Debug 面板可以）
2. Skill 的成功必须由 Verifier 判定
3. LLM 不参与实时控制，也不能宣布成功
4. 一切跨层/跨进程消息结构化并带 schema_version
5. 视觉 / 感知 / 运动三者的频率域分离，不允许互相等
6. 任何新能力都必须能被"可演示 + 可量化"地验收
```

---

## 8. 明确不承诺

```text
- 不承诺视觉直接给出 5 cm 级精度（需要 Mode C 与多次观察配合）
- 不承诺仔细理解能回答任意问题（只承诺触发式场景描述与未知物解释）
- 不承诺单目深度在 Phase 1 可用
- 不承诺一开始就有全身人类级物理运动
- 不承诺用 LLM 解决实时控制问题
```

低层实现（程序化 IK、RigGraph 约束、RL 策略）都可以替换，**上层接口不变**。
