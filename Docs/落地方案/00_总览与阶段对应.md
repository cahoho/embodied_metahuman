# 00｜落地方案总览

> `落地方案` 只放**可执行的工程计划**；架构、原则、契约、验收标准的权威定义在 `Docs/理论框架`。
> 两份目录的关系：理论框架说"为什么这样设计"，落地方案说"这一阶段具体怎么做、怎么验收"。

## 1. 工程基线（所有落地方案共用）

```text
编辑器     团结引擎 Tuanjie 1.10.0（内核 2022.3.62t12）
渲染       URP 14.2.0-t1
角色动画   团结 Rig Graph  cn.tuanjie.riggraph 1.0.0   ← 取代 Animation Rigging
学习       ML-Agents 2     com.unity.ml-agents 2.0.2（推理用 Barracuda 3.0.0）
导航       内置 com.unity.modules.ai（NavMesh）；未装 AI Navigation 包
外部服务   Python（FastAPI + OpenCV + Ultralytics）视觉理解服务
工程路径   H:\Unity_Projects\embodied_metahuman
```

任何方案中出现新包、新 API 时，必须与上表一致；不得引入 Animation Rigging、Unity 6 专有 API。

## 3. 每份落地方案必须包含的结构

```text
0. 这份方案是什么（范围 / 非目标 / 前置事实）
1. 目标与非目标（可观测的判定方式）
2. 总体架构（进程拓扑、频率域、启动顺序）
3. 关键设计决策与取舍（含被否决的替代方案）
4. 接口契约（跨进程 / 跨层消息）
5. 实现细节（代码骨架与踩坑点）
6. 可观测性（Debug 面板、遥测、告警阈值）
7. 验收标准（可量化，逐条通过 / 不通过）
8. 里程碑（每个里程碑都能独立演示）
9. 与后续阶段的接口边界
10. 风险与对策
11. 附录（参数默认值、示例消息、参考链接、术语）
```

---

## 4. 三条通用验收要求

```text
1. 可复现：固定场景 + 一条命令跑完整验收 + 输出报告
2. 可降级：外部依赖（Python 服务、VLM、模型）缺失时系统仍能运行降级形态
3. 可演示：每个里程碑结束时都有一段能录屏的演示，而不是"全都做完才能看到东西"
```
